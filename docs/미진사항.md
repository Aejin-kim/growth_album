# 프로젝트 진행 상황 및 미진 사항 정리

## 1. 진행 완료 사항 (Done)
- **아키텍처 정립 (V2):** 로컬 저장소 의존성을 완전히 제거하고 Supabase 클라우드 기반의 아키텍처로 전환 완료.
- **레거시 클린업:** 더 이상 사용하지 않는 로컬 이미지 폴더(`data/images`), 로컬 JSON(`data/photos.json`), 그리고 구형 백엔드 API 로직(`server.js` 내 파일 조작 부분) 삭제 완료.
- **문서 단일화:** `architecture_history.md` 삭제 및 `architecture.md`로 최신화 통합.
- **DB 정제:** 기존에 로컬 경로를 바라보던 깨진 사진 데이터들을 Supabase DB에서 삭제 완료.
- **환경 검증:** Supabase 프로젝트 복구 및 DNS 연결 상태 정상 확인.

## 2. 미진 사항 및 향후 과제 (Pending)
- **Supabase Storage 영구 저장 로직 미구현:**
  - 현재 구글 포토 API가 제공하는 링크는 **60분 후 만료**됨.
  - 이를 해결하기 위해 2단계 동기화 시 이미지를 Supabase Storage(`photos` 버킷)로 업로드하고 영구 URL을 발급받는 로직이 구현되어야 함.
- **사용자 선행 작업 필요:**
  - Supabase 대시보드에서 `photos`라는 이름의 **Public Bucket** 생성이 필요함. (보안 정책상 수동 생성 필수)
- **이미지 로딩 최적화:**
  - Storage 저장 시 웹 최적화된 해상도로 리사이징하여 업로드하는 로직 검토 필요.

## 3. 기술적 제약 사항 확인
- **Google Photos Picker API 제약:** 세션이 종료된 후에는 고유 ID(Media Item ID)만으로 실시간 링크 재발급이 불가능함을 확인. 따라서 초기 연동 시(60분 이내) 별도 저장소(Storage)로의 복제가 필수적임.
